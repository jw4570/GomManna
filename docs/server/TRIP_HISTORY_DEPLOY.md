# 여행 기록 서버 변경 — 로컬 구현

현재 상태: 로컬 C++ PostgreSQL 구현·마이그레이션·테스트. 운영 DB·AWS 배포는 수행하지 않음.

## 포함 범위

- 종료된 본인 모임 목록과 만료 시각, 상세 멤버·마킹 조회
- 기본 OFF인 별도의 여행 기록 공유 설정; 철회 시 이후 조회 차단
- 전체 공유 회차의 멤버별 경로 페이지 조회
- 메모 수정 이력과 각 메모에 마지막 첨부된 사진 조회·삭제
- 이력에 연결된 사진의 삭제 대기열 보호 및 개인 삭제·자동 파기 연계

초기 마이그레이션은 현재 메모만 복사한다. 과거 덮어쓴 기록은 복원되지 않는다.
여행 제목은 방 제목이며 실제 방문 도시를 추론하거나 별도 여행지 필드를 저장하지 않는다.
영상 생성은 서버 기능이 아니다. iOS가 페이지별 기록을 받아 지도·프로필을 시간순으로 합성하고 AVAssetWriter로 내보내는 작업이 별도로 필요하다.

## 보존 및 권한 결정

기존 48시간 자동 정리 규칙을 연장하지 않는다. expires_at_ms는 종료·공유 OFF·비활동 기한 중 가장 빠른 값이다.
종료 전에 이미 정리된 데이터는 누락될 수 있다. "종료 후 48시간 전체 기록"을 보장하려면 보존 정책 변경과 별도 구현이 필요하다.
중간 탈퇴자는 본인 기록만 조회하고 타인에게 기록을 제공하지 않는다.
남아 있던 참가자도 기본적으로 타인의 콘텐츠를 볼 수 없으며 작성자의 trip_history_shared 동의가 필요하다.
영상에 포함되거나 외부로 저장된 정보는 이후 철회나 서버 파기로 회수할 수 없다.

## 적용 순서

1. 최신 운영 연결 프로젝트와 서버 버전, 마이그레이션 적용 이력을 확인한다. 이 문서의 실행 대상은 개인키나 개발용 DB가 아니다.
2. iOS 기록 공유 설정과 정책 설명을 먼저 준비한다. 기본 OFF를 유지하고 기존 위치 공유 동의를 재사용하지 않는다.
3. 기존 서버 프로세스를 모두 중단한다. 구버전 사진 정리 작업은 trip_notes 참조를 모르므로 동시 실행하면 안 된다.
4. DB 관리자로 기존 v2 마이그레이션 이후 `supabase/migrations/202611220001_gommanna_trip_history.sql`을 실행한다.
5. 새 C++ 서버를 빌드·배포한다. 새 서버는 스키마 버전 3이 없으면 시작하지 않는다.
6. 합성 테스트 계정으로 기본 OFF, 타인/탈퇴자 접근 제한, 동의·철회, 계정·모임 데이터 삭제, 만료 및 사진 물리 삭제를 검증한다.
7. 대응 iOS 빌드에서 최근 여행과 기록 조회를 연결한다. 예전 라이브 API의 종료 후 접근 제한을 변경하지 않는다.

구버전 서버만 다시 시작하는 롤백은 금지한다. 새 이력을 남겨 둔 채 구버전 사진 정리 코드를 실행하면 사진이 유실될 수 있다.
실패 시 서버를 멈춘 상태로 원인을 수정하거나, 관리자가 이력·대기열 참조를 검토해 별도 롤백 계획을 작성한다.

## 검증

CMake: `-DGOMMANNA_BUILD_HTTP_DB_TESTS=ON`으로 PostgreSQL 테스트를 빌드한다.
실제 운영 DB를 테스트 대상으로 사용하지 않는다.

- `trip_history_real_db`: 실제 PostgreSQL에서 목록·이력·동의·철회·탈퇴자 권한·삭제·만료 검증
- `trip_http_real_db`: HTTP 인증·JSON·페이지 제한·이력 조회·동의 철회 검증
- 기존 사진 테스트: 새 이력 참조 동안 사진 유지, 만료·계정 삭제 후 정리 검증

새 여행 API는 메모리 Fake 구현에 추가하지 않았으며 그 모드에서는 501이다.
UI Preview용 Mock은 후속 iOS 작업에서 동일 API 계약에 맞춰 추가한다.
